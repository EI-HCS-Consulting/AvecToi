**⚠️ Règle Git STRICTE (CLAUDE.md) :** chaque modification, même un correctif ponctuel, part sur une branche neuve (depuis `origin/main` à jour) et se termine par sa propre PR poussée sur GitHub — jamais de nouveau commit ajouté à une branche dont la PR est déjà mergée. **Autorisation permanente : commit + push + PR dès qu'une tâche de code est terminée et vérifiée, sans attendre que l'utilisateur le redemande.** **L'utilisateur merge lui-même, puis teste** (le merge déclenche la publication OTA — sauf si la modif ajoute une nouvelle dépendance native, auquel cas un `eas build` + réinstallation complète de l'APK est nécessaire). Toujours vérifier l'état réel d'une PR via `gh pr view <n> --json state,url` plutôt que de supposer — ce repo merge vite, souvent en un seul message de l'utilisateur.

**⚠️ Convention UI (CLAUDE.md, section "Conventions UI", ajoutée #268) :** toute nouvelle confirmation doit utiliser le composant thémé `ConfirmModal`, jamais `Alert.alert` (natif, hors charte) ; tout nouveau bouton doit reprendre les couleurs/emoji/style déjà en usage à l'écran ; toute notification éphémère doit réutiliser le pattern `showToast` existant. Vérifier ce point avant toute PR ajoutant un popup ou un bouton, pour éviter une PR d'harmonisation de rattrapage.

## 1. Objectif de la session
