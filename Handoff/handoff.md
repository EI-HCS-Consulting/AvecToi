**⚠️ Règle Git STRICTE (CLAUDE.md) :** chaque modification, même un correctif ponctuel, part sur une branche neuve (depuis `origin/main` à jour) et se termine par sa propre PR poussée sur GitHub — jamais de nouveau commit ajouté à une branche dont la PR est déjà mergée. **Autorisation permanente : commit + push + PR dès qu'une tâche de code est terminée et vérifiée, sans attendre que l'utilisateur le redemande.** **L'utilisateur merge lui-même, puis teste** (le merge déclenche la publication OTA — sauf nouvelle dépendance native, qui nécessite un `eas build` + réinstallation complète). Toujours vérifier l'état réel d'une PR via `gh pr view <n> --json state,url` plutôt que de supposer.

**⚠️ Convention UI (CLAUDE.md, "Conventions UI") :** toute nouvelle confirmation utilise `ConfirmModal` (jamais `Alert.alert` natif) ; tout nouveau bouton reprend les couleurs/emoji/style déjà en usage à l'écran ; toute notification éphémère réutilise le pattern `showToast` existant.

## 1. Objectif de la session
Quatre PR distinctes, toutes déjà mergées par l'utilisateur avant le début de cette session documentaire, livrées sur la demande initiale « Besoin récurrent » puis trois itérations de retours utilisateur successifs après test réel en production :
- **PR #453** (`feat/besoin-recurrent`) : réglage « 🔁 Besoin récurrent » dans l'assistant « Publier » (Hebdomadaire / Quinzaine / Tous les X jours, date de fin, aperçu plafonné à 52 besoins) — création de toute la série en un seul lot partageant `recurrence_group_id` (nouvelle colonne `tasks`, migration `20260914_task_recurrence_group.sql`), même mécanisme d'annulation 8s que la création groupée de checklist. Couvre Repas/Affaires/Administratif/Autre/Courses, Transport et Relais hors scope.
- **PR #454** (`feat/besoin-recurrent-date-obligatoire`) : le champ date, jusque-là facultatif en « Autres options », devient obligatoire dès l'écran de catégorie (« 📅 Ajouter une date ») pour Repas/Affaires/Administratif/Autre et Courses — débloque directement le réglage de récurrence, sans étape de blocage intermédiaire ; popup de récurrence restructuré (rappel de la date de début, calendrier de fin qui surligne en orange l'ancrage et les occurrences prévues via un nouveau prop `highlightDates` sur `MiniCalendar`).
- **PR #455** (`feat/besoin-recurrent-round2`) : bouton de récurrence passé à un libellé sur 2 lignes avec le vrai jour de la semaine ; bouton dédié à la date de fin dans les écrans Repas et Courses une fois la récurrence réglée ; suppression en cascade généralisée aux besoins issus d'une série récurrente (même mécanisme que la suppression groupée de checklist, discriminant `kind: "checklist" | "recurrence"` sur `deleteBatchTarget`) ; ajout du champ `recurrence_group_id` manquant au type `Task` (`lib/types.ts`).
- **PR #456** (`feat/besoin-recurrent-claim-serie`) : le popup « Je m'en occupe » (formulaire prénom/nom/photo/précision), qui glissait encore depuis le bas alors que les autres popups liés sont déjà centrés, est désormais centré au milieu de l'écran sur toutes ses étapes (`relaisClaimStepCentered`, devenu inutile, supprimé) ; sur un besoin issu d'une série récurrente encore ouverte sur d'autres dates, un nouveau switch « Cette date / Toute la série » (`claimAllRecurrence`, `recurrenceSiblings()`) permet de prendre en charge en un seul geste toutes les occurrences encore ouvertes (identité, photo, précision, et pour Courses l'attribution des articles) ; le popup de remerciement indique combien d'autres dates ont été prises en charge en même temps.
