## État global du projet

**Stack :** React Native + Expo SDK 51+, Expo Router, Supabase (BDD/Auth/Storage/Realtime/Edge Functions), EAS Build + EAS Update (channels development/preview/production, `expo-updates`, publication OTA automatique sur push `main` via `.github/workflows/eas-update-preview.yml`). expo-notifications, expo-calendar, expo-image-picker, expo-sharing (partage simple) + react-native-share (partage groupé multi-fichiers, dépendance native ajoutée #245). Resend (transactionnel) branché sur les Edge Functions. Stripe côté web uniquement. Supabase CLI bloqué sur cette machine (App Control Policy Windows) : déploiement des migrations/Edge Functions exclusivement via le Dashboard Supabase, jamais auto-appliqué par Claude.

**⚠️ Règle Git STRICTE (CLAUDE.md) :** chaque modification, même un correctif ponctuel, part sur une branche neuve (depuis `origin/main` à jour) et se termine par sa propre PR poussée sur GitHub — jamais de nouveau commit ajouté à une branche dont la PR est déjà mergée. **Autorisation permanente : commit + push + PR dès qu'une tâche de code est terminée et vérifiée, sans attendre que l'utilisateur le redemande.** **L'utilisateur merge lui-même, puis teste** (le merge déclenche la publication OTA — sauf si la modif ajoute une nouvelle dépendance native, auquel cas un `eas build` + réinstallation complète de l'APK est nécessaire). Toujours vérifier l'état réel d'une PR via `gh pr view <n> --json state,url` plutôt que de supposer — ce repo merge vite, souvent en un seul message de l'utilisateur.

**⚠️ Convention UI (CLAUDE.md, section "Conventions UI", ajoutée #268) :** toute nouvelle confirmation doit utiliser le composant thémé `ConfirmModal`, jamais `Alert.alert` (natif, hors charte) ; tout nouveau bouton doit reprendre les couleurs/emoji/style déjà en usage à l'écran ; toute notification éphémère doit réutiliser le pattern `showToast` existant. Vérifier ce point avant toute PR ajoutant un popup ou un bouton, pour éviter une PR d'harmonisation de rattrapage.

## 1. Objectif de la session
Suite directe du dernier handoff (#309, qui s'arrêtait à #308) : trois nouvelles demandes utilisateur sur l'écran Entraide. (a) Étendre au visiteur la sélection multiple + suppression en masse par appui long, jusque-là réservée à l'admin, mais strictement limitée aux besoins que ce visiteur a lui-même publiés. (b) Faire passer en rouge l'intérieur du pictogramme Entraide de la barre d'onglets quand un besoin Urgent n'est pas pris en charge. (c) Ajouter une petite cloche rouge à côté du pictogramme quand un besoin a été publié par quelqu'un d'autre et n'a pas encore été vu.

(a) s'est avéré une simple extension de gating UI : `deleteOrSoftDeleteTasks` (logique de suppression déjà existante) calculait déjà correctement "mine" vs "others" par auteur pour l'admin comme pour un visiteur — aucun changement backend nécessaire, seul le calcul du booléen `selectable` sur chaque carte a changé. (b)+(c) ont nécessité un nouveau hook `lib/entraideBadges.ts` (état badges + suivi "vu" par AsyncStorage) et un nouveau composant `components/EntraideTabIcon.tsx`, câblés dans les deux `_layout.tsx` (admin/visiteur) — ce qui a exigé de restructurer `app/(admin)/_layout.tsx` pour que `space.id` soit accessible au niveau où `Tabs.Screen` est défini. Livré comme **PR #311**, mergée.

Juste après le merge de #311, l'utilisateur a remonté un crash (capture d'écran Metro) : `Error: cannot add 'postgres_changes' callbacks for realtime:entraide-badges:<uuid> after subscribe()`, avec une pile d'appel remontant à `EntraideTabIcon`. Root cause : react-navigation/bottom-tabs invoque `tabBarIcon` plusieurs fois en parallèle pour un même onglet (passes de mesure/animation) — deux montages concurrents du hook tentaient de créer un canal Supabase Realtime de même nom fixe, le second héritant du canal déjà `.subscribe()`d du premier et plantant sur son `.on(...)`. Correctif générique (suffixe aléatoire par montage dans le nom du canal, sans chercher à empêcher les doubles montages eux-mêmes) livré comme **PR #312**, mergée.

Après test sur le Dev Build, ajustement demandé : revenir à la couleur normale du thème pour l'icône (pas de remplissage rouge conditionnel), et remplacer la "cloche" par un second point rouge — les deux signaux devenant deux points rouges indépendants empilés façon « : » (haut = urgent non pris en charge, bas = nouveau besoin d'un autre auteur). `EntraideTabIcon.tsx` réécrit en conséquence, livré comme **PR #313**, mergée.
