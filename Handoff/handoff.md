Toujours vérifier l'état réel d'une PR via `gh pr view <n> --json state,url` plutôt que de supposer — ce repo merge vite, souvent en un seul message de l'utilisateur.

**⚠️ Convention UI (CLAUDE.md, section "Conventions UI", ajoutée #268) :** toute nouvelle confirmation doit utiliser le composant thémé `ConfirmModal`, jamais `Alert.alert` (natif, hors charte) ; tout nouveau bouton doit reprendre les couleurs/emoji/style déjà en usage à l'écran ; toute notification éphémère doit réutiliser le pattern `showToast` existant. Vérifier ce point avant toute PR ajoutant un popup ou un bouton, pour éviter une PR d'harmonisation de rattrapage.

## 1. Objectif de la session
Suite directe du dernier handoff (#294, qui s'arrêtait à #293) : cycle de 6 PR sur le flux checklists suggérées / Mur d'Entraide, plus un correctif calendrier. **#295** corrige trois points signalés après test : un bug de closure empêchait la synchronisation Mensuel→Hebdo de suivre le bon jour sélectionné ; l'import privé d'une checklist depuis Mon Compte était bloqué à tort par l'anti-doublon public du Mur (désormais l'anti-doublon public ne s'applique qu'en activant "Publier aussi sur le Mur d'Entraide") ; et la carte d'un besoin de relais ponctuel gagne une traçabilité admin des réponses "Pas cette fois". **#296** rétablit la suppression en cascade du reste d'une checklist suggérée publiée (perdue lors d'un refactor antérieur), aussi bien en suppression individuelle qu'en masse, Mon Compte et Entraide. **#297** est la PR fonctionnelle principale du cycle : elle ajoute le choix de la destination de publication d'une checklist suggérée (Mur seul / Mes Checklists seul / les deux, avec synchronisation automatique entre les deux copies liées), donne à l'auteur d'un besoin (visiteur inclus, pas seulement l'admin) le droit de le supprimer lui-même, et une première tentative de correctif du bouton "Retour" du wizard d'import. **#298** et **#299** sont deux itérations de correctifs post-test sur cette même PR #297 : #298 corrige la synchronisation du statut "Fait" entre les copies liées et quelques irritants UI, mais le bug "Retour" persiste ; #299 en trouve la cause racine — deux `<Modal>` React Native restaient simultanément `visible=true`, ce qu'Android ne supporte pas correctement — et fusionne les 3 Modals du flux Entraide en un seul avec bascule de contenu interne, en plus d'enchaîner plutôt que superposer les popups de suppression liée. **#300** applique le même correctif "Retour" à l'écran équivalent mais indépendant de Mon Compte (`components/MyChecklist.tsx`, qui a son propre picker/wizard distinct de `components/Entraide.tsx` — point de confusion déjà noté en mémoire, cf. `avectoi_mychecklist_separate_import_flow.md`), suite à un nouveau signalement utilisateur avec captures d'écran montrant le même symptôme sur cet écran-là. L'utilisateur a mergé #300 puis demandé de générer un handoff — la commande standard de CLAUDE.md.

État "done" : atteint pour le code — PR #295 à #300 sont toutes mergées, confirmées explicitement par l'utilisateur au fil des messages ("mergé / ok"). La partie handoff (ce fichier + le docx + le PRD) est finalisée dans cette session, reste à committer/pousser/ouvrir la PR docs.
