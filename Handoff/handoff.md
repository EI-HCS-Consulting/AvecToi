**⚠️ Règle Git STRICTE (CLAUDE.md) :** chaque modification, même un correctif ponctuel, part sur une branche neuve (depuis `origin/main` à jour) et se termine par sa propre PR poussée sur GitHub — jamais de nouveau commit ajouté à une branche dont la PR est déjà mergée. **Autorisation permanente : commit + push + PR dès qu'une tâche de code est terminée et vérifiée, sans attendre que l'utilisateur le redemande.** **L'utilisateur merge lui-même, puis teste** (le merge déclenche la publication OTA — sauf nouvelle dépendance native, qui nécessite un `eas build` + réinstallation complète). Toujours vérifier l'état réel d'une PR via `gh pr view <n> --json state,url` plutôt que de supposer.

**⚠️ Convention UI (CLAUDE.md, "Conventions UI") :** toute nouvelle confirmation utilise `ConfirmModal` (jamais `Alert.alert` natif) ; tout nouveau bouton reprend les couleurs/emoji/style déjà en usage à l'écran ; toute notification éphémère réutilise le pattern `showToast` existant.

## 4. Ce qui a échoué
Rien pendant cette session (documentation uniquement, aucun code écrit). Pour référence future : la navigation vers « Paramètres Co-Administrateur » a nécessité 4 tentatives avant #413 (PR #407, #408, #409/#410 — voir `git log -- components/CoAdminSettingsOverlay.tsx` et les commits associés). Cause racine des deux premiers échecs (#407/#408) : un `router.push` vers une route du groupe `(admin)` depuis un écran du groupe `(visitor)` ciblait un `<Tabs>` navigator jamais monté pour un visiteur (chaque groupe Expo Router a sa propre arborescence de navigateurs) — la navigation échouait silencieusement ou affichait un écran vide. #409/#410 ont contourné le problème avec un overlay absolu-fill manuel (fonctionnel mais avec un bouton « ✕ Fermer » que l'utilisateur ne voulait pas). #413 résout le problème à la racine en montant la route cible **dans le groupe `(visitor)` lui-même** (onglet caché du même `<Tabs>` déjà monté) plutôt qu'en tentant de naviguer vers un autre groupe : plus besoin d'overlay ni de bouton de fermeture manuel, le comportement natif de fermeture d'onglet (retap sur un autre onglet) suffit. À retenir pour toute future navigation cross-rôle dans ce repo : ne jamais `router.push` vers une route d'un groupe Expo Router différent de celui actuellement monté sans vérifier qu'un navigateur existe bien pour la cibler.
