## 1. Objectif de la session
Trois volets sur "Mes Modèles" (checklists privées réutilisables entre espaces patients d'un même intervenant), chacun demandé après confirmation du merge du précédent : (1) le bouton "Mes Modèles" ne proposait pas encore d'import : cliquer un modèle devait ouvrir un popup listant tous ses items (y compris ceux déjà "faits" ailleurs) pré-cochés, avec possibilité de décocher les items non pertinents avant import. (2) Après merge : permettre la désélection d'items déjà couverte, ajouter un appui long sur une checklist perso/importée pour en confirmer la suppression, et vérifier un signalement de régression (import direct sans popup). (3) Après merge : changer le texte d'intro du popup, empêcher les doublons à l'import, permettre de compléter une checklist déjà partiellement importée dans le même groupe, et griser un modèle entièrement déjà importé avec un popup informatif "J'ai compris" renvoyant vers Mon Compte / Checklists.

État "done" : atteint — PR #225, #226 et #227 mergées, chacune confirmée par l'utilisateur ("Mergé", "Mergé / ok") avant de passer à la demande suivante.

## 2. État actuel
Tout le travail de ce cycle est concentré dans un seul fichier, `components/MyChecklist.tsx` (composant partagé Mon Compte admin/visiteur/intervenant) :
- **Popup de sélection d'items** (`importTpl`/`tplChecked` + `openTemplateImport`/`toggleTplItem`/`toggleAllTplItems`/`confirmImportTemplate`) : remplace l'ancien import direct. Liste tous les items du modèle avec case à cocher, "Tout cocher/décocher", et un bouton "Importer (n)" qui n'importe que les items cochés restants.
- **Anti-doublons global** (`findExistingChecklistItem`) : recherche un titre d'item dans l'ensemble des `personal_checklist_items` de l'espace patient courant, tous groupes confondus (pas seulement le modèle en cours de réimport). Les items dupliqués sont pré-décochés, grisés et non cliquables dans le popup ("déjà dans ce dossier patient").
- **Complétion incrémentale** : réimporter un modèle déjà partiellement présent ajoute les items manquants au même groupe (`custom_checklist_name` identique) — aucune logique de lot séparée, le regroupement par nom du modèle suffit déjà.
- **Modèle entièrement importé** (`fullyImportedTplName`) : la carte du modèle est grisée dans la liste "Mes Modèles" ("Checklist déjà entièrement importée dans cet espace patient") ; cliquer dessus ouvre un `ConfirmModal` en mode `singleButton` ("J'ai compris") qui referme le popup sans importer et laisse l'utilisateur sur la section Checklists de Mon Compte.
- **Suppression par appui long** (`deleteGroupConfirm`/`deleteGroupSaving`/`confirmDeleteGroup`) : `onLongPress` sur l'en-tête d'un groupe de checklist perso/importée ouvre un `ConfirmModal` de confirmation ; à la confirmation, supprime la tâche Mur d'Entraide liée (si `task_id`) puis tous les items du groupe, et referme le groupe s'il était affiché.
- **Texte d'intro du popup** changé en "Choisis les items qui sont adaptés à ce patient."

**Dernière action avant ce handoff :** génération de ce handoff, demandée par l'utilisateur juste après confirmation du merge de la PR #227.
